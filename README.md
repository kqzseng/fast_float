# qtx_float

[![Crates.io](https://shields.io)](https://crates.io)
[![Documentation](https://docs.rs)](https://docs.rs)
[![License](https://shields.io)](#license)

A zero-allocation, high-performance fixed-point decimal library designed for financial, quantitative, and high-frequency trading (HFT) order book data.

---

## Core Advantages

- **Zero Heap Allocation**: All parsing, conversion, and mathematical operations are performed entirely on the stack. This completely avoids the performance overhead brought by frequent OS heap memory allocations in high-concurrency environments.
- **Universal float! Macro**: No manual type annotation required. A single macro syntax dynamically captures and routes all native formats (strings, floats, and various integer types/literals) with zero runtime cost.
- **Eliminate Floating-Point Distortions**: Features an adaptive anti-distortion filtering algorithm that detects and strips precision noise generated by binary floating-point (IEEE 754) accumulation (e.g., accurately reconstructing `0.30000000000000004` back into `0.3`).
- **Business-Grade Precision Rules**:
  - **Integer Path**: When parsing a pure integer input (such as `"123000"`), trailing zeros are strictly preserved, and the `scale` factor remains `0`.
  - **Decimal Path**: When parsing a number with a decimal point (such as `"123.000"`), trailing zeros are preserved explicitly to lock the required precision.
- **Smart Rounding Division**: Division operations default to retaining the maximum `scale` of the two operands. Excess precision is rounded using standard round-half-up entirely within the integer domain, avoiding conventional intermediate float conversion errors.

## Installation

Add this dependency to your `Cargo.toml`. By default, it maintains a lightweight footprint with zero external dependencies, allowing you to selectively enable advanced extension features:

```toml
[dependencies]
# 1. Core ultra-fast version (zero extra dependency overhead)
qtx_float = "0.3.0"

# 2. Mix and match advanced feature toggles:
# qtx_float = { version = "0.3.0", features = ["ser", "pgsql", "mysql"] }
```

### Feature Toggles

- **ser**: Enables Serde serialization and deserialization support.
- **pgsql**: Enables SQLx PostgreSQL database lossless mapping support (maps directly to NUMERIC/DECIMAL).
- **mysql**: Enables SQLx MySQL database lossless mapping support (maps directly to DECIMAL).

## Quick Start Examples

### 1. Universal Construction via the float! Macro

```rust
use qtx_float::float;
use qtx_float::Float;

fn main() {
    // Adaptive parsing from a string literal
    let f_str = float!("123.456"); 
    assert_eq!(f_str, Float::new(123456, 3));

    // Native floating-point literal (automatic anti-distortion noise removal)
    let f_noise = float!(0.1 + 0.2); // Actually 0.30000000000000004 under the hood
    assert_eq!(f_noise, Float::new(3, 1)); // Perfectly restored to 0.3

    // Native integer variable or literal (automatically sets scale to 0 and keeps zeros)
    let val_u8: u8 = 8;
    assert_eq!(float!(val_u8), Float::new(8, 0));
    assert_eq!(float!(5000), Float::new(5000, 0));

    // Explicit traditional two-argument construction (value, scale)
    assert_eq!(float!(12345, 2), Float::new(12345, 2));
}
```

### 2. Math Operations and Compound Assignment

```rust
use qtx_float::float;

fn main() {
    let mut price = float!("1500.50"); // 1500.50 (scale 2)
    let tick_size = float!("0.25");    // 0.25 (scale 2)

    // Supports +=, -=, *=, /=, %= compound assignment operators
    price += tick_size;
    assert_eq!(price, float!("1500.75")); 

    // Division operation: Adaptively retains the max scale precision with round-half-up
    let a = float!("2.00"); // 2.00 (scale 2)
    let b = float!("3");    // 3 (scale 0)
    // 2.00 / 3 = 0.6666... result retains max scale (2 digits) and rounds up -> 0.67
    assert_eq!(a / b, float!(67, 2));
}
```

### 3. Optional Feature: Serde Serialization (features = ["ser"])

When the `ser` feature is active, `Float` is serialized externally into a clean decimal string (preventing large-number precision truncation in frontend JavaScript clients), while deserialization effortlessly accommodates mixed types:

```rust
use qtx_float::float;
use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize)]
struct Order {
    id: u64,
    price: qtx_float::Float,
}

fn main() {
    // Serialization test: Automatically formats into a decimal string with exact precision
    let order = Order { id: 1, price: float!("15.50") };
    let json = serde_json::to_string(&order).unwrap();
    assert_eq!(json, r#"{"id":1,"price":"15.50"}"#);

    // Deserialization test: Safely processes mixed numeric types or distorted floating points
    let incoming = r#"{"id":2,"price":0.30000000000000004}"#;
    let decoded: Order = serde_json::from_str(incoming).unwrap();
    assert_eq!(decoded.price, float!("0.3"));
}
```

### 4. Database Integration (features = ["pgsql"] / ["mysql"])

By enabling the corresponding database feature, `Float` can be used directly as a high-precision fixed-point number (NUMERIC/DECIMAL) for dual-way lossless persistence without any heap allocation. It integrates seamlessly with SQLx's `FromRow` macro and parameter bindings:

```rust
// Seamless row model mapping, eliminating Decode/Type error risks
#[derive(sqlx::FromRow, Debug, PartialEq)]
struct DBStockItem {
    id: i64,
    symbol: String,
    price: qtx_float::Float, // Automatically binds to high-precision DB decimals
}

// 1. PostgreSQL integration example (features = ["pgsql"])
async fn pg_example(pool: &sqlx::PgPool) -> Result<(), sqlx::Error> {
    sqlx::query("INSERT INTO items (price) VALUES ($1)").bind(float!("68500.2500")).execute(pool).await?;
    let item: DBStockItem = sqlx::query_as("SELECT id, symbol, price FROM items LIMIT 1").fetch_one(pool).await?;
    Ok(())
}

// 2. MySQL integration example (features = ["mysql"])
async fn mysql_example(pool: &sqlx::MySqlPool) -> Result<(), sqlx::Error> {
    sqlx::query("INSERT INTO items (price) VALUES (?)").bind(float!("68500.2500")).execute(pool).await?;
    let item: DBStockItem = sqlx::query_as("SELECT id, symbol, price FROM items LIMIT 1").fetch_one(pool).await?;
    Ok(())
}
```

## Recommended Profile for Production

To allow the compiler to maximize cross-module/cross-file inline expansions, it is highly recommended to configure single-unit Link-Time Optimization (LTO) in the root project's `Cargo.toml`:

```toml
[profile.release]
opt-level = 3
lto = true
codegen-units = 1
panic = "abort"
strip = true
```
